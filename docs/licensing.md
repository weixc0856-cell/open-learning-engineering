# 知识产权与版权审计指南 (Licensing & IP Guide)

在开源知识库的建设过程中，对第三方知识产权的尊重是项目可持续发展的基石。

---

## 一、双重许可证策略深度解读

```text
├── 教学内容 (docs/)        ──> CC BY-NC-SA 4.0 (非商业共享)
└── 工程代码 (labs/, projects/) ──> MIT License (宽松商用自由)
```

### 1. 为什么文档选用 CC BY-NC-SA 4.0？
- **保护开放初衷**：防止商业培训机构未经许可将社区的心血直接包装成高价封闭课程。
- **鼓励衍生传播**：允许学习者、高校教师自由引用、翻译、改良并继续用于公益教学，但必须注明出处并以相同许可证开源。

### 2. 为什么代码选用 MIT License？
- **降低工程落地阻力**：学习者在学习实验后，往往希望将代码片段、框架设计复用到自己的企业项目、工业系统或商业软件中。MIT 协议赋予了最宽泛的代码复用自由。

---

## 二、第三方权威教材的合规处理边界

在引用哈佛、MIT、伯克利、斯坦福等高校资料及出版书籍时，必须遵守以下四条铁律：

| 资源类别 | 示例 | 正确的处理方式 | 严禁的侵权行为 |
| :--- | :--- | :--- | :--- |
| **开源许可教材** | MIT Missing Semester, D2L | 深度映射章节，吸收其教学逻辑并结合工程实验重新推导 | 直接全文镜像、冒充原创作品 |
| **CC BY-NC-ND 教材** | Linux Command Line (TLCL), Cosmic Python (部分) | 仅提供官方原版阅读入口与思考题索引，用自己的话独立讲解 | 逐句翻译、重排出版或制作衍生衍生讲义 |
| **商业版权出版物** | 各种出版社纸质书籍 | 购买学习、吸收原理，仅在文献中规范引用其定理和页码 | 上传未经授权的扫描版 PDF 或批量抄袭正文 |
| **官方技术规范** | NVIDIA CUDA Guide, MDN, Python Docs | 引用权威定义、说明版本、用真实代码验证机制 | 误将官方文档等同于宽松开源代码 |

详细的逐项审计记录参见 [docs/references/license-audit.md](references/license-audit.md)。
